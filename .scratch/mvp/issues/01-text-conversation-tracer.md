# 01: 文字对话最小链路

**What to build:** 打通一条从浏览器到 LLM 的最小完整链路：用户在对话页用文字和真乃聊天，角色的回复流式返回日语原文和中文字幕，两者都写入对话记录。这一步搭好后端（Python）、前端（Next.js）和 Docker Compose 的骨架，并建立一个不依赖语音的「对话引擎」，后续的语音、检索、记忆都叠加在它之上（见 spec「整体结构」）。暂时只用一个默认用户和一份写死的最小人设。同时搭好切入点 A 的测试框架：用假 LLM 通过后端对外接口驱动文字对话回合。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 一条命令就能启动前端和后端（Docker Compose），打开对话页可以用文字和真乃对话
- [ ] 对话引擎是一个独立模块，输入为用户、角色、对话、输入文本，输出为日语原文和中文字幕
- [ ] LLM 提供方先实现 OpenAI 兼容 Chat Completions 接口，地址、密钥、模型名都可以配置
- [ ] 对话模型一次输出结构化结果（日语原文和中文字幕），流式解析后逐步推送到前端（ADR-0001）
- [ ] 前端同时显示用户的输入、角色回复的日语原文和中文字幕
- [ ] 对话记录（用户输入、日语原文、中文字幕）被持久化，重新打开对话页可以看到
- [ ] 测试框架就绪：后端使用 pytest；假 LLM 能记录收到的提示词，并能按剧本返回结构化回复；至少有一个通过后端对外接口驱动的文字对话回合测试
