# 02: 访问密钥与用户

**What to build:** 引入用户和访问密钥。管理员通过命令行为某位用户签发访问密钥，也可以吊销；一位用户可以持有多把密钥。用户在设置页填入密钥后才能对话，对话记录归属到这位用户。记忆、档案、对话记录都挂在用户上，而不是挂在密钥上（见 `CONTEXT.md` 中的「访问密钥」）。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 管理员可以通过命令行创建用户、为用户签发访问密钥、吊销某把密钥
- [ ] 没有密钥、密钥无效或密钥已被吊销时，后端接口拒绝请求，前端显示明确的提示
- [ ] 同一位用户的两把密钥访问的是同一份对话记录
- [ ] 吊销一把密钥后，该用户的数据不受影响，用另一把密钥仍然可以访问
- [ ] 设置页可以填入并保存访问密钥（保存在浏览器本地）
- [ ] 移除 01 中的默认用户，所有请求都根据访问密钥确定对应的用户
- [ ] 以上行为都有通过后端对外接口驱动的测试
