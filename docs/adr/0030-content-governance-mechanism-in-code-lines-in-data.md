# 内容治理：机制在代码，线在数据；审查在边界，不回溯存储

本条是本仓库的内容治理原则（2026-10-23 定），来自维护者在 QuickQuip 的 `sensitive_filter` 中验证过的设计。它约束本线未来一切涉及内容闸门的功能：**作者出售拉杆，不出售方向**——代码只提供机制，判断放在部署者持有、gitignored 的数据里；谁承担部署环境的风险，谁持有那条线（风险与控制同址）。具体六条：

1. **机制与价值分离**：任何词表/分级/边界配置默认为空或仅含无争议项（如反诈）；类别名由部署者自定，分类学建议只进文档、不进出厂数据。
2. **默认放行，举证责任在拦截方**：观察级（只记录）与拦截级分离，晋升拦截需要命中证据；假阳性比漏报更有害。
3. **审查在边界，不回溯存储**：命中只在传输接触面（模型输入/输出、工具参数与结果、生成服务提交前）替换或拦截，数据库中的原文永不因此销毁。
4. **日志最小泄露**：命中日志只记环节、类别与词条哈希前缀，后台接口只给计数——审查自身的产物不得成为监控资产。
5. **不参加军备竞赛**：这一层是绊网（tripwire），不是对抗意志坚定的对手的堡垒；为压低漏报引入大规模归一化（拼音、谐音）而让假阳性爆炸，不做。
6. **边界诚实**：不假装覆盖非文本模态；未覆盖的链路在文档里写明，不靠暗示制造安全错觉。

## 与继承 ADR 的关系

- **ADR-0023（照片全年龄、写死无开关）**：本条与其冲突之处在判断的归属，不在「全年龄」这个结果。稳定期（ADR-0029）不改动照片代码，0023 原样有效；本线触碰照片功能时另立 ADR supersede 0023 的「写死无开关」，届时那条线由部署者数据决定，结果本身不预设。
- **ADR-0006、0012、0017**（管理者看不到用户内容、加密备份有保留期、密钥只存浏览器）：隐私立场与本条同源，本条使它们更强而非更松。
- **ADR-0003、0009**（素材不进仓库、风险自担）：「风险与控制同址」的既有先例。gitignored 词表与 AGPL 的兼容沿用 corpus 先例——部署者的实例运维数据不是修改后的程序源码，不随源码义务分发。
- **角色层拒答不在本条 scope**：人设硬性规则（「不接受越界要求，用她的方式岔开」）、不该说的话与好感度是**内容与数据**（sheets 是数据文件，fork 可改），是角色的品格而非基础设施层的替代判断。本条反对的是后者。

## Considered Options

- **维持上游模式（线焊死在代码、无开关、自带密钥也绕不开）**：与「为任何目的运行」的精神冲突，部署者的风险与其控制权分离；本仓库不采用。
- **完全不做审查层，把一切交给上游模型/服务商**：对中文公网部署不现实——平台与辖区的现实风险没有人承担。不采用。
- **机制在代码、线在数据（本条）**：机制可以造得极强（多接缝覆盖、Aho-Corasick 级的工程），但方向归持有风险的人。

## Consequences

- 未来任何内容闸门功能按此验收：代码只含机制；判断放部署者数据；默认从宽、拦截 opt-in；只在边界替换、不回溯存储；日志按最小泄露设计。
- 文本侧目前是空白（上游只有照片 tag 黑名单与角色拒答）：把 QuickQuip 式 tripwire 移植进回合管线是本条的第一个候选应用。
- 动照片功能时，supersede ADR-0023 的新 ADR 引用本条；GLOSSARY 的「照片」等条目随代码实际变化同步修订（稳定期不动）。
- 本仓库的公开产物（代码、`.example`、文档）不携带任何一方的价值立场；部署者之间的分歧留在各自的 gitignored 配置里。
